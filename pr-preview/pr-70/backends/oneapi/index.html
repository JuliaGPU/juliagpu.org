Intel oneAPI

Support for Intel GPUs, from integrated graphics to Arc and Data Center GPU Max, with array operations, kernel programming and oneMKL.

oneAPI.jl documentation oneAPI.jl

oneAPI.jl makes it possible to program Intel GPUs from Julia. It talks to the GPU through Level Zero, the low-level interface underneath Intel’s oneAPI toolkit.

Like the other JuliaGPU back-ends, oneAPI.jl can be used at several levels: with the oneArray array type and Julia’s array operations, by writing kernels in Julia and launching them with @oneapi, or directly through the Level Zero API in the oneL0 submodule.

Installation

oneAPI.jl requires Julia 1.10 or later and runs on Linux, or experimentally on Windows through WSL2. It supports the GPUs that Intel’s Compute Runtime driver supports: integrated graphics from Tiger Lake onwards and the discrete Arc GPUs (the A series needs Linux 6.2 or later), as well as the Data Center GPU Max GPUs in the Aurora supercomputer. The Compute Runtime, oneMKL and the other libraries are downloaded as Julia packages, so you don’t need to install the oneAPI toolkit, but your user does need access to the GPU, which on most distributions means being a member of the render group. Install the package with Julia’s package manager:

pkg> add oneAPI

oneAPI.versioninfo() shows the versions of the downloaded components and the GPUs that were found, which makes it the first thing to run, and to include in bug reports:

julia> using oneAPI

Array programming

A oneArray is a Julia array that lives in GPU memory. Operations on it, like broadcasting and reductions, run on the GPU:

julia> a = oneArray(rand(Float32, 2, 3))
2×3 oneArray{Float32, 2, oneAPI.oneL0.DeviceBuffer}:
 0.0308319  0.193295  0.0890354
 0.568051   0.945077  0.728369

julia> b = a .* 2 .+ 1
2×3 oneArray{Float32, 2, oneAPI.oneL0.DeviceBuffer}:
 1.06166  1.38659  1.17807
 2.1361   2.89015  2.45674

julia> sum(b; dims=2)
2×1 oneArray{Float32, 2, oneAPI.oneL0.DeviceBuffer}:
 3.626324
 7.4829917

julia> Array(b)
2×3 Matrix{Float32}:
 1.06166  1.38659  1.17807
 2.1361   2.89015  2.45674

Accessing individual elements from the CPU is not allowed by default, because it is very slow, so code that does so needs to be expressed in terms of array operations instead. Also note that many Intel GPUs, especially integrated ones, do not support Float64, so it is best to work with Float32 data.

Linear algebra is handled by Intel’s oneMKL library: matrix multiplication and other BLAS operations from the LinearAlgebra standard library call oneMKL, sparse matrices are available as oneMKL.oneSparseMatrixCSR and related types, and fft from AbstractFFTs.jl works on a oneArray. The oneMKL chapter of the documentation covers what else is wrapped.

Kernel programming

When array operations are not enough, you can write a kernel as a Julia function and launch it with @oneapi, specifying the number of work-items per work-group (items) and the number of work-groups (groups). Inside the kernel, functions like get_global_id() return the 1-based index of the current work-item:

julia> function vadd(a, b, c)
           i = get_global_id()
           @inbounds c[i] = a[i] + b[i]
           return
       end
vadd (generic function with 1 method)

julia> a = oneArray(rand(Float32, 1024)); b = oneArray(rand(Float32, 1024));

julia> c = similar(a);

julia> @oneapi items=256 groups=4 vadd(a, b, c);

julia> Array(c) ≈ Array(a) + Array(b)
true

To write kernels that also run on other vendors’ GPUs, use KernelAbstractions.jl, which oneAPI.jl supports through its oneAPIBackend.
